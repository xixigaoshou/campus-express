🔧 本轮发现并修复的问题

问题 1（首轮 FAIL：B20c/B21）— 接单者手动取消订单后 taker_id 未清空

接单者取消已接订单后订单退回待接单，但 t_order.taker_id 仍保留原接单者（B20c 断言 taker=16）。cancelOrder 场景二使用 order.setTakerId(null); orderMapper.updateById(order)，而 MyBatis-Plus 的 updateById 默认不更新 null 字段，置空未生效。

修复：改用 LambdaUpdateWrapper 显式 .set(Order::getTakerId, null) 更新状态、取消原因、接单者与更新时间，与定时任务②的写法一致。

问题 2（首轮 FAIL：G2c/G2d/G2e）— 定时任务②自动取消链路未生效

此前定时任务②仅存在于手动模拟方法中未被调度执行；本次回归前已补上 @Scheduled(fixedDelay = 60_000) 的 timeoutRemindCancelTask() 并加入幂等控制（同单只提醒一次）、状态历史与通知。本轮 G 组 10 项全部通过，验证了自动取消会清空接单者、扣 5 信誉分、写历史并通知发布者。

问题 3（首轮 FAIL：G2 系列）— 后端运行旧编译产物

IDEA 启动的后端（22:18）早于代码修复（23:3x~0:03），加载的是旧 class。本轮已用 Maven 重新 clean package 并切换为 java -jar 运行最新 jar 后，全部用例通过。

问题 4（工程）— Maven 构建受沙箱与文件锁影响

① 沙箱禁止写入 D:\develop\apache-maven-3.9.4\mvn_repo（settings.xml 指定），改用 -Dmaven.repo.local 指向工作区缓存副本解决；② 运行中的进程会锁住 jar 导致 clean 失败，需先停止旧进程再构建。
